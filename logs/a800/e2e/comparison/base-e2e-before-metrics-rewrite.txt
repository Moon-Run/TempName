# 模型端到端验收：BF16 静态 tile 重排

本文给出模型端到端验收方案。原生Megatron小型GPT的TP=4完整训练环路已在作业178562通过功能检查；Flux模型接入、配对输出/梯度检查和三策略整步性能验收仍未完成，不能将原生训练跑通视为候选策略的模型收益。阶段3机制状态和已有算子结果见 [base.md](base.md)。

## 三种测量的边界

| 测量 | 回答的问题 | 当前状态 |
| --- | --- | --- |
| 无插桩 GEMM-RS 算子 | 排序是否降低完整算子的 GPU 延迟？ | 178474/178475 已完成三策略对照 |
| 四来源 tile 采样 | 哪个贡献最后到达，排序如何改变到达时间和 join skew？ | 178525完成7200条正确性记录；原12/18窗口准入不能用于尾tile，子集审查发现开销超标，机制仅保留探索性线索，见base.md的P2修正 |
| 模型训练一步 | 算子改善是否降低整个模型的训练时间？ | 原生GPT功能基线178562已跑通；Flux接入及模型性能对照尚未执行 |

当前算子计时由 CUDA Events 包围重复的 `op.forward`，包括融合 GEMM/写入、全局 barrier 和最终归约，以各 rank 中最慢者汇总；不包括模型其他层、反向传播和 optimizer。采样 forward 的时间还受 marker、轮询和提交间隙影响，只用于机制诊断。

Nsight Compute 缓存/访存计数器权限不足限制机制归因，但不阻止无 profiler 的模型整步计时。小规模模型验证可以在 BF16 阶段开展，无需等待 FP8；阶段6再完成更广的模型、规模和配置验证。

- 固定单节点 4×A800、TP=4、BF16；初次验证保持 DP=1、PP=1。模型层数、hidden size、FFN size、序列长度、micro/global batch、梯度累积、sequence parallel、activation checkpointing、融合选项和 CUDA Graph 设置全部写入配置。
- 用独立诊断运行记录实际触发的 GEMM-RS：模块名称、前向/反向阶段、每步次数、输入布局、全局 M/N/K 和每 rank 局部尺寸。当前算子每 rank 输入为 `[M,K/TP]`，输出为 `[M/TP,N]`，必须与模型的数据分片语义一致。
- 检查候选真正进入目标 kernel，而不是只加载了库。报告目标调用数、实际替换数、回退数及原因。额外 profiler 运行可用于观察占比和重叠，不能把重叠 kernel 时长之和当作模型关键路径占比。
- 首次性能对照不临时调参追求最好结果。实际模型出现未验证的 shape，先补该 shape 的映射、边界和数值检查；不支持 cohort 填充槽位或分区对齐条件的调用保留原始实现。所有 rank 的策略选择必须一致。

若候选没有覆盖真实模型的目标调用，先解决接入或代表性问题；不能把这种配置的零收益解释为算法无效。

## 2. 固定对照与正确性门槛

主对照是原始 Flux、`remote_first`、`interleaved`，三者共用 IPC 修复、精度、hparams 和归约选项。原始框架的 GEMM+NCCL 可以作为另列的系统参考；排序的收益以共同 Flux 基线衡量。

先对三种策略使用相同权重、输入、RNG 状态和训练状态进行配对检查：

1. 目标层输出及分片语义正确，特别检查 sequence parallel 下的 ReduceScatter/AllGather 配对。
2. 整体 logits/loss、输入梯度、参数梯度、一次 optimizer 更新后的参数均通过检查；验证 autograd 集成、通信依赖和缓冲区生命周期。
3. 连续运行预定的短训练序列，loss 和梯度无 NaN/Inf，偏差符合事先规定的数值预算。短序列只验证运行与数值稳定性，不声称长期收敛等价。

在正式性能采样前，保存各检查对象的 max-abs、relative-L2 等误差指标及阈值。阈值依据所选模型、BF16 原始重复运行的变化和可行的 FP32 子集参考确定；不得直接把算子的 `atol=rtol=0.02` 当作整模型 loss/梯度标准，也不得看到候选结果后放宽阈值。

性能窗口之间恢复相同的模型、optimizer、RNG、数据位置及其他可变状态，或重放同一段训练状态。不能让三个策略依次训练到不同参数状态后直接比较。

## 3. 正式测整个 optimizer step

主指标为同步墙钟测得的 `ms/optimizer step` 和有效训练 `tokens/s`。一步包含全部梯度累积 microsteps 的 forward、loss、backward、optimizer 更新及一致的清梯度操作。

- 首轮定义为数据已在 GPU 上的稳定训练计算吞吐；排除数据读取、H2D、初始化/编译、预热、checkpoint 和评估，报告中写明此边界。需要应用整体吞吐时，另加包含数据准备的完整训练循环测量，不能混用两种口径。
- 每个计时窗口开始前完成预热、rank 对齐和 GPU 同步，随后记录单调墙钟；执行固定数量的完整 optimizer steps，结束时等待本 rank 全部 GPU 工作完成，再记录墙钟。计时窗口内部不新增逐算子同步；保留模型本身的依赖与重叠。
- 每个 rank 独立计算本地 elapsed，窗口以最大 elapsed 除以 step 数汇总。跨 rank 只比较时长，不相减各自的绝对时间戳。
- `tokens/s = 窗口内全局有效 token 数 / 窗口秒数`；TP=4 处理同一份 token，不能再乘4。梯度累积只按实际样本/token 计一次，padding/mask 的口径固定并记录。
- profiler、tile 采样和硬件计数器在独立运行中采集；正式窗口关闭这些诊断。

建议先用短预试确定足够的预热和窗口长度，再冻结配置。正式采用三策略的六种排列，每个策略在各位置出现次数相同；至少在两个独立 Slurm 分配中复测，优先保持同一组 GPU，记录 UUID、拓扑、驱动、频率/温度和全部原始窗口。独立作业不是跨节点验证，跨节点结果需分层报告。

报告每个配置的绝对 step 时间、tokens/s、窗口分布及相对原始的配对延迟下降率 `1-T_candidate/T_original`。吞吐增长率与延迟下降率分别计算。置信区间以独立配对窗口为单位；同一窗口的多步不作为大量独立样本。保留全部窗口和异常原因，不能只挑最快的一轮。

## 4. 通过、无收益和未完成如何区分

| 验收项 | 通过条件 | 未满足时的解释 |
| --- | --- | --- |
| 接入 | 目标调用实际命中候选，替换覆盖率与回退原因完整 | 尚不能评价目标实现的模型收益 |
| 正确性 | 输出、梯度、更新后参数及短训练检查达到预先冻结的标准 | 不进入性能结论 |
| 整步性能 | 两个独立作业的配对方向一致，预先指定的95%配对区间支持正收益，且达到事先约定的实用阈值 | 区间跨零则收益未确定；稳定负值则报告退化 |
| 适用范围 | 每个预定模型配置分别报告，保留弱收益与退化配置 | 单个最好配置不能代表通用收益 |

实用阈值在预试后、正式测量前冻结，可结合测量噪声和部署价值决定；不把任意微小正点估计称为验收通过。若只有目标层变快、整步无明确改善，则结论就是“算子收益已确认，模型收益未确认”。

机制解释单独验收：join skew 下降不等于最后贡献提前，分区最后坐标的 tile 也不一定是实际最后完成的 tile。即使观察到采样尾部与算子边界同向变化，仍须考虑轮询、采样扰动、rank 启动偏斜和局部性变化。现有硬件计数器缺失时保留归因限制；不以模型收益代替机制证据，也不因计数器不可用阻止模型性能测量。

## 四组端到端实施与数值准入记录（2026-10-02）

用户本轮要求同时比较原生Megatron、原始Flux、远端重排和交替重排。新增入口为`tools/a800/e2e/`，使用原生`GPTModel`、无流水线forward/backward schedule、DDP梯度缓冲/最终同步和FP32主权重的Apex Adam。原生组保留原始RowParallelLinear；Flux三组只替换8个attention输出投影/MLP第二线性层的前向GEMM-RS，反向为原生语义的sequence AllGather、dgrad和wgrad GEMM。实际shape为`(M,N,K_global)=(1024,1024,1024)`和`(1024,1024,4096)`，每optimizer step为4个microsteps、32次目标调用。

### “冻结值”和误差的含义

“冻结值”是测试前固定的数值验收上限；“误差”是候选输出与参考输出的实际差异。本轮候选的参考是原生BF16 Megatron；独立BF16/FP32对照用于制定上限。冻结后，不因某个候选刚好超标就调宽上限。

- 最大绝对误差：`max_i |候选_i - 参考_i|`，表示差异最大的一个元素差了多少。
- relative-L2：`||候选 - 参考||₂ / ||参考||₂`，表示整个张量的差值向量，相对于参考张量有多大。实现对接近零的参考使用RMS=1e-6的分母下限；下面这个bias没有触发该下限。
- 两个指标都在门槛内才通过。当前门槛按每个张量在两个独立原生校准种子、四rank中的最大误差取2倍，是经验验收预算，不是通用数值标准或95%置信区间。

例如远端策略第一次Adam更新后的`decoder.layers.0.pre_mlp_layernorm.bias`：

| 指标 | 实测误差 | 冻结上限 | 判断 |
| --- | ---: | ---: | --- |
| 最大绝对误差 | 0.000198364 | 0.000389103 | 通过 |
| relative-L2 | 12.2165% | 12.1508% | 未通过 |

12.2165%只描述这个bias张量，不表示整个模型、loss或所有梯度错了12%。该bias初始为0，第一次更新后参考值的RMS约为0.0001001，分母较小，因此小的绝对差也可能对应较大的相对比例。当前按冻结规则保留失败，不把“接近门槛”视为通过。
